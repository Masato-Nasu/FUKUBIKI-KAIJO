# 福引会場

2011年に制作したAndroidアプリ「福引会場」を、スマートフォン・タブレットで使えるPWAとして再制作しました。
昔ながらの商店街のガラポンを、お店や企業イベントで楽しめます。

**[福引会場を開く](https://masato-nasu.github.io/FUKUBIKI-KAIJO/)** · [MASATO LAB](https://masato-lab.pages.dev/)

## できること

- 指の動きに追従して抽選器を回す。1回転の途中で玉が出て、お皿へ放物線を描いて落下。
- 主催者名・イベント名、賞の種類数・名前・景品・本数・玉の色を自由に設定。
- 玉の総数と残りの玉を管理。本番では対象景品の残数に比例した抽選を行い、当選した景品を1つ減らす。
- 鐘・ラッパ・ピアノ・和風・レトロの5つの当選音セット。各セットに特賞・当たり・参加賞・はずれの音を用意。
- 参加賞以外の当たりでは、2011年版の動画から取り出した鐘の音と、鐘を振る演出の後に当選画面と音楽を表示。
- 抽選履歴、端末内保存、JSONバックアップ・復元。初回の読み込みとオフライン準備後は通信なしで利用可能。

## 店舗で使う

1. 起動時は毎回「おためし」です。本番の景品残数と履歴は保持され、おためしでは消費しません。
2. 右下の「設定」で暗証番号を作り、主催者・イベント・景品・玉の総数を登録します。
3. おためしで確認後、「本番」を選んで保存し、確認画面から開始してください。
4. 抽選結果を確認して景品を渡したら、店員が結果画面の「福」を2回続けてタップして次の抽選を許可します。本番のお客さま用画面にはこの操作案内を表示しません。
5. 終了時はバックアップを書き出してください。「新しい抽選会を準備」は履歴を消し、各景品の開始時の本数を復元します。

再読み込みした場合も、おためしで起動します。以前の結果を起動直後に再表示しません。結果の記録は履歴に残ります。本番を続ける場合は設定から再度、本番へ切り替えてください。

## 抽選と保存

Web Cryptoの棄却法で偏りのない整数を生成し、抽選対象の残数に比例して決定します。IndexedDBの1つのreadwriteトランザクションで残数の減算・履歴・未確認結果を保存してから演出を始めます。

「上位賞を序盤に出さない」をONにすると、各景品の「何回目から」を本番で適用します。対象になった景品の残数に比例した抽選です。途中で抽選対象がなくなる設定は保存前に検出します。

1台の端末・同じブラウザでの運用を前提としています。複数端末で残数を共有する機能はありません。ブラウザのサイトデータ削除、プライベートモード、公開元の変更などで保存データを利用できなくなることがあります。定期的にバックアップしてください。

管理用暗証番号はPBKDF2 SHA-256で保存します。端末を解析できる人に対する強固な認証ではありません。バックアップには暗証番号を含めず、復元時は現在の暗証番号を維持します。

## PWA

iPhoneはSafariの共有から「ホーム画面に追加」、Android・PCは対応ブラウザのインストール機能で追加できます。サーバーへの個別の利用者登録は不要です。

## 構成・公開

HTML / CSS / JavaScriptの静的アプリです。ビルド・npm installは不要です。GitHub Pagesは`main`ブランチのルートから公開します。

Cloudflare Pagesに公開する場合は、このフォルダで実行します。

```sh
npx wrangler pages deploy . --project-name fukubiki-kaijo --branch main
```

ローカル確認はHTTPSまたはlocalhost上の静的HTTPサーバーを利用してください。
